# C++ 线程池（手写学习版）

一个用 C++17 手写的固定线程数线程池，用来练习 `thread` / `mutex` / `condition_variable` 的组合使用。

## 特性

- 固定 N 个工作线程，线程复用，不随任务数量增长
- 空闲线程阻塞在条件变量上，不空转、不占 CPU
- `Submit()` 接受任意可调用对象（lambda、函数、仿函数）
- `Stop()` 优雅停止：执行完队列中剩余任务后再回收线程，可重复调用
- 禁用拷贝，避免线程池被意外复制

## 文件

```
thread_pool.hpp   线程池实现（单头文件，直接 include）
main.cpp          用法示例：4 个线程跑 10 个任务
```

## 编译运行

```bash
g++ -std=c++17 -O2 -Wall -Wextra main.cpp -o thread_pool_demo
./thread_pool_demo
```

输出示例：

```
任务 0 由线程 0xbc 执行
任务 1 由线程 0xcc 执行
...
全部任务执行完毕
```

任务编号顺序不固定是正常的——多个工作线程并发取任务，谁先抢到谁执行。

## 设计要点

三个组件：

| 组件 | 作用 |
| --- | --- |
| `std::vector<std::thread>` | 固定的工作线程 |
| `std::queue<std::function<void()>>` | 任务队列 |
| `mutex` + `condition_variable` + `bool stop` | 保护队列、让空闲线程睡眠、通知退出 |

工作线程循环里最容易写错的三处：

1. **等待条件是 `stop_ || !tasks_.empty()`**：有活或者要停止都该醒来。写成两个条件都满足才醒，正常运行时就永远不干活。
2. **取到任务后先解锁再执行**：持锁执行任务会让其他线程无法入队/取任务，任务里再提交任务就直接死锁。
3. **退出条件是 `stop_ && tasks_.empty()`**：停止后要把队列里剩下的任务跑完，任务不能丢。

`Stop()` 里也有两个必须的点：

- 置标志后要 `notify_all()`，否则睡着的线程永远不醒；
- `join()` 必须在锁外进行，否则工作线程拿不到锁检查退出条件，互相等待 → 死锁。

## 已验证

- 4 线程执行 10 个任务，全部执行、无遗漏
- 输出加锁后不交叉
- `Stop()` 可重复调用，析构自动停止，程序正常退出
- `g++ -std=c++17 -Wall -Wextra` 零警告

## 可以继续做的方向

- `Submit` 返回 `std::future`，支持取任务返回值（`packaged_task`）
- 任务异常捕获，避免一个任务抛异常终止整个进程
- 有界任务队列 + 背压（队列满时阻塞或拒绝提交）
- 区分优雅停止与立即丢弃任务
- work-stealing：每个线程一个双端队列，空闲时去别的队列偷任务
